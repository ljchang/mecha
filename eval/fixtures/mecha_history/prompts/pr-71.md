# A turn's tool output is budgeted against the whole window, not the room left

**Crate:** `mecha-core` (`src/pressure.rs`, `ContextTracker`; `src/agent.rs`, `run_tools`)

## What is wrong

Each turn's tool results share one byte budget, `[tools] output_budget_bytes` (`ToolCtx::output_budget_bytes`), split evenly across the turn's calls and floored at `tool::SPILL_FLOOR_BYTES`. The figure is derived once from the context window, so that one turn's results cannot jump the gap between the compaction threshold and the window. But late in a run the real gap is much smaller: it is whatever is left between where the transcript is now and the threshold. A turn that arrives near the threshold can still add a full window-sized budget of output, which is the overflow the budget exists to prevent.

The context tracker in `pressure.rs` already predicts the next request's token count from the transcript's bytes at its measured tokens-per-byte rate. Nothing uses that to size a turn's output.

## What fixed looks like

**In the tracker.** Add a method on `ContextTracker` that answers how many bytes of tool output the next turn can add before the transcript crosses a token `limit`, given the transcript's current size in bytes:

- It is `None` when the tracker has no anchor yet (no response observed), the same as `predict`.
- Otherwise take the predicted tokens for the current bytes, the room is `limit` minus that, saturating at zero, and the answer is the room converted to bytes at the tracker's measured tokens-per-byte rate (`room / tokens_per_byte`, truncated). A denser measured rate therefore affords fewer bytes.
- For example, after `observe(10_000, 30_000)`, a limit of 30,000 tokens with 30,000 bytes of transcript affords 60,000 bytes, a limit of 12,000 affords 6,000, and a limit of 9,000 affords 0.

**In the loop.** Each turn's tool-output budget becomes the configured budget narrowed by that figure:

- It is a minimum, so it can only narrow. A run with room to spare gets exactly the configured budget, and the first turn (no anchor yet) is unchanged.
- It narrows only when `spill_dir` is set. With a spill directory, over-cap bytes are moved to a file and the model is told where they are, so narrowing relocates output rather than losing it. With no spill directory, the configured budget stands.
- With no compaction threshold for the run, the configured budget stands.
- The per-result floor at `SPILL_FLOOR_BYTES` still applies.
- The threshold is the one the loop already uses for compaction, and the transcript size is `pressure::message_bytes` over the current messages.

## Interface

In `mecha_core::pressure`:

```rust
impl ContextTracker {
    pub fn affordable_output_bytes(&self, limit: u64, current_bytes: usize) -> Option<usize>
}
```
