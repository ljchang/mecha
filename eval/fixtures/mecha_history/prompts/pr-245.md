# The front door hands a privileged run whatever dates the extractor reports

**Crates:** `mecha-core` (`src/frontdoor.rs`, `src/grounding.rs`), `mecha-cli` (`commands/frontdoor.rs`, `tui/frontdoor.rs`)

## What is wrong

A request from a stranger is read by a quarantined extractor. `Record::for_privileged_run` is the quarantine's boundary: it hands a run with tools a typed extraction and never the prose. One field, `extracted.dates_mentioned`, is the extractor's list of dates "as written in the text". The prompt says to invent nothing, but nothing checks that, so a date the model made up crosses the boundary as a fact about the request. And since containment is the only thing that could be checked, a long "date" that is really an instruction copied verbatim out of the prose would pass a plain containment check too.

`grounding::admit`, the existing check that a quote is a literal span of a referent, also has a hole: a `min_quote_chars` of zero admits an empty quote, and every text contains the empty string.

## What fixed looks like

**Grounding.**

- `admit` refuses with `Refusal::QuoteTooShort` whenever `min_quote_chars` is zero, whatever the quote.
- `Refusal` gains a `QuoteTooLong` variant, for a caller that applies its own ceiling. `admit` itself still has no ceiling.

**The record.** On `frontdoor::Record`:

- Constants for the shortest and the longest span a date may be: `DATE_MIN_CHARS = 3` and `DATE_MAX_CHARS = 48` (characters).
- A method that splits the extractor's dates into `(grounded, ungrounded)` against the record's prose (the same `Record::prose` the extractor read, joined with newlines, as a single referent):
  - Each entry is trimmed and has wrapping `"` stripped. An entry that is then empty is skipped and lands in neither list.
  - An entry longer than `DATE_MAX_CHARS` is ungrounded with `QuoteTooLong`, before any containment check.
  - Otherwise it goes through `grounding::admit` with `DATE_MIN_CHARS` as the floor. Admitted, the stripped span goes into `grounded`. Refused, the entry exactly as the extractor wrote it goes into `ungrounded`, with the refusal.
  - With no extraction, both lists are empty.
- A method returning just the ungrounded list.
- An associated function giving one phrase per refusal, shared by the CLI and the TUI. It is exhaustive over `Refusal`. `QuoteNotInReferent` is "not in the text as written", `QuoteTooShort` is "in the text, but shorter than a date anyone wrote", `QuoteTooLong` says it is longer than a date anyone wrote and was not handed over, and the other two variants read "not grounded".
- `for_privileged_run` hands over only the grounded dates as `extracted.dates_mentioned`.

**The owner's views.** `mecha frontdoor show` and the TUI's detail pane print the grounded dates on the `dates_mentioned` line. When any are ungrounded, they add a warning line, then each ungrounded date with its phrase, then a note that this is a label on the record, not a block.

Anything built from the brief, the Slack card among them, now carries only grounded dates. An existing test whose fixture reports a date its prose never says needs that date put in the prose.

## Interface

In `mecha_core::grounding`:

```rust
pub enum Refusal {
    // ...existing variants...
    QuoteTooLong,
}
```

In `mecha_core::frontdoor`:

```rust
impl Record {
    pub const DATE_MIN_CHARS: usize;
    pub const DATE_MAX_CHARS: usize;
    pub fn dates_by_grounding(&self) -> (Vec<String>, Vec<(String, crate::grounding::Refusal)>)
    pub fn ungrounded_dates(&self) -> Vec<(String, crate::grounding::Refusal)>
    pub fn date_finding(reason: crate::grounding::Refusal) -> &'static str
}
```
