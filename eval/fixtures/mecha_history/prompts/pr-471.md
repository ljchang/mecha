# The web chat's test doors write into the owner's real store

**Crate:** `mecha-cli` (`src/commands/serve/chat.rs`, with the call sites in `src/commands/serve/mod.rs` and `src/commands/serve/archive.rs`)

## What is wrong

The web chat's state (`ChatState`) decides where a chat's transcript and workspace go by resolving the default locations at the moment they are needed: the sessions directory under the mecha home, and the `web` producer directory under the work directory. Every reader and writer in `serve` resolves them again, call by call.

Tests build their own `ChatState` through the test constructors in `chat.rs`. Those constructors fix the outbox to the real default root, and nothing fixes the sessions or work locations at all. So every test that drives a chat writes real transcripts and workspaces into the owner's own `~/.mecha`, on every test run. And because the locations are resolved from the process-wide mecha home, a test door running beside another test that has temporarily moved the home adopts that test's directory instead of its own.

## What fixed looks like

- A `ChatState` holds where its transcripts and its chats' workspaces live, decided once when it is built. `serve` resolves the real defaults at construction. Every path that reads or writes a transcript or a chat workspace (resume, the archive, uploads, listing) uses the state's own locations, never a fresh lookup.
- A test door gets a fresh temporary directory of its own for its transcripts, its workspaces and its outbox. That directory sits under the system temporary directory, never under the mecha home, and never under a directory another test has moved the home to. Two test doors never share one.
- Nothing about where `serve` writes for a real owner changes.

## Interface

In `mecha-cli/src/commands/serve/chat.rs`, on `ChatState`:

```rust
sessions_dir: PathBuf,   // field: where this door's transcripts are
work_dir: PathBuf,       // field: where this door's chats' workspaces are

pub(super) fn sessions_dir(&self) -> &std::path::Path;
```
