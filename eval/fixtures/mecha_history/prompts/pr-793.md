# Code mode: `fs_list` should hand a program names, not a handle

**Crate:** `mecha-core` (`src/tool/code.rs`, `src/tool/mod.rs`, `src/tool/builtin.rs`, `src/replay_run.rs`, `src/interpreter/mod.rs`)

## Problem

Inside a `code` program every tool result is a handle, so a call like `.startswith` on an `fs_list` entry fails. The worked example never skips subdirectories. 256 tool reads per program is too few.

## Desired behaviour

**Marking listing tools**

- Add a `Tool` method that says whether a tool's result is directory names, one per line.
- It defaults to false. Only the builtin `FsList` returns true; a server tool that happens to be named `fs_list` does not.
- `ReplayTool` forwards the method.
- `Admission::over` records which admitted tools are listing tools. That set takes part in equality.

**What a program gets back**

- A successful result from a listing tool reaches the program as a list of `str`.
- `fs_list`'s "(empty directory)" text becomes an empty list.
- The names count toward peek's byte cap and counter. A listing that would go past the cap is refused whole, with peek's `LimitError` and a message starting `peek bytes:`.
- A failed listing still raises `ToolError`.

**The description**

- With a listing tool admitted, the handle sentence becomes `<names joined by " and "> returns a list of names (str; a directory's ends in /). Every other tool returns a handle, not text`.
- Otherwise it stays `A tool returns a handle, not text`.
- In both cases it is followed by today's colon and list.

**The worked example**

- Move it into a constant.
- Show it only when the `fs_list` listing and `fs_read` are both admitted.
- Change it to iterate names directly and skip any entry ending in `/`.
- Keep its search pattern and its final `print`, and make sure it runs as written.

**Limits**

`defaults::TOOL_READS` becomes 2048. `COUNTED_HOST_LIMITS` stays the sum of the counted limits.

## Interface

`mecha_core::tool::code`:

```rust
const EXAMPLE: &str
impl Admission { pub fn listings(&self) -> impl Iterator<Item = &str> }
impl Run { fn listing(self, names: impl IntoIterator<Item = String>) -> Self }
```

Trait `mecha_core::tool::Tool`: `fn lists_names(&self) -> bool` (default false).
