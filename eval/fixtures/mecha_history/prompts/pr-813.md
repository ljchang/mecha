# Anthropic provider: a tool schema with a top-level combinator fails every request

**Crate:** `mecha-core` (`src/provider/anthropic.rs`, request body construction in `Anthropic::body`)

## What is wrong

The Anthropic Messages API rejects a tool whose `input_schema` has `anyOf`, `oneOf` or `allOf` at its **top level**. The error is an HTTP 400, and it fails the whole request, not just that tool. MCP servers are free to publish schemas like that. A typical case is "give either this field or that pair of fields", written as an `anyOf` of `required` lists.

So a single MCP tool written this way makes every run that offers it unusable on the Anthropic provider. Other providers accept the same schemas, and the tool's own validation still enforces the rule whatever the schema says.

## What fixed looks like

When the Anthropic provider builds the `tools` array:

- A schema with no top-level combinator is sent exactly as it is today, byte for byte, together with its description.
- A schema with one or more top-level combinators has them removed from the copy that is sent. The tool's own spec is not modified.
- If removing them leaves the schema without a `type`, add `"type": "object"`.
- Every other key is kept unchanged, including combinators nested inside `properties`, which the API accepts.
- The removed rules move into the tool's description so the model still sees them. The description sent starts with the original description text. After it comes a short sentence saying the input must also satisfy these schema rules, which the tool checks.
- Each removed rule is written as the keyword, a colon and a space, then its value serialized as compact JSON (`serde_json`'s default `to_string` form). For example: `oneOf: [{"required":["a"]},{"required":["b"]}]`. Several rules are joined with `; `.

Keep this inside the Anthropic provider. The OpenAI-compatible provider and the tool registry should not change, and the agent loop must not learn anything about it. Placing the prompt-cache breakpoint on the tools works as before.
