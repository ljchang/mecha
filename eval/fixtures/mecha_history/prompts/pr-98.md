# Distill notices when the world disagrees with what the graph told the agent

**Crates:** `mecha-core` (`src/distill.rs`), `mecha-cli` (`commands/distill.rs`)

## Problem

`mecha distill` turns a session into an episode for the knowledge graph. The distiller model reports the episode text and **corrections**: places where the user told the agent it was wrong. Nothing captures a different and equally useful signal: the agent said or believed something because the graph told it so, and something else in the same session (an email, a search result, a calendar entry, a file) disagreed. For example, the agent said a deadline was the 14th because the graph said so, and an email in the session says the 9th. Nobody corrected anyone, and nothing proposes a fix, but a person would want to know so they can decide whether to chase it (for instance with `mecha gossip --entity <about>`).

## Desired behaviour

**A new record.** Add a `Surprise` to `distill.rs`, separate from `Correction`: what was predicted from the graph, what was actually found, and optionally who or what it is about. It names no fact id and carries no repair. It serializes with `about` omitted when absent.

**The distiller's contract.**

- The distiller's system prompt explains surprises (the world disagreeing with the agent's memory, as opposed to the user correcting the agent) and adds a `surprises` array to the reply format, each entry `{"predicted", "actual", "about"}` with `about` optional. Either array may be omitted.
- `parse_distiller_reply` reads `surprises` as leniently as it reads `corrections`: a missing or `null` array, a non-array, or a junk entry costs nothing else. An entry that does not parse, or whose `predicted` or `actual` is blank, is dropped on its own.
- `Distilled` gains the surprises. A reply that is a skip, with no episode and no corrections but at least one surprise, still returns `Some`: a surprise alone is worth keeping.

**What leaves the session.** A surprise's text is the model's own reading of transcript prose, so it is gated exactly like corrections:

- Add a gate beside `corrections_for` that returns all the surprises for a known, trusted timeline (taint known and not untrusted) and none otherwise. Unknown taint counts as untrusted.
- `upsert_args` takes the surprises as a new last argument, unfiltered, applies the gate itself, and puts the sendable ones under `meta.surprises` when there are any. The key is absent otherwise. The episode body is never withheld because of this.

**What the owner sees.** `mecha distill` prints every surprise for each session it distills, whether or not anything is pushed, as one line naming the session id, the `about` when present, and the predicted and found text. A person reading their own terminal is a safe place for this text. When the gate would withhold the surprises (untrusted or unknown timeline), each line is marked as unverified, and warns not to paste `about` into a command unread.

## Interface

In `mecha_core::distill`:

```rust
#[derive(Debug, Clone, PartialEq, Eq, Deserialize, Serialize)]
pub struct Surprise {
    pub predicted: String,
    pub actual: String,
    pub about: Option<String>,
}

pub struct Distilled {
    pub episode: String,
    pub corrections: Vec<Correction>,
    pub surprises: Vec<Surprise>,
}

pub fn surprises_for(taint: Option<Taint>, surprises: &[Surprise]) -> &[Surprise]

pub fn upsert_args(
    session_id: &str,
    source_ref: &str,
    occurred_at: &str,
    body: &str,
    taint: Option<Taint>,
    distilled_by: &str,
    corrections: &[Correction],
    appraisal: Option<&crate::appraisal::Appraisal>,
    surprises: &[Surprise],
) -> Value
```
