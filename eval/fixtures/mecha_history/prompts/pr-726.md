# Nightly diagnosis replays the corpus's largest model, loading it over the resident one

**Crates:** `mecha-cli` (`commands/diagnose.rs`, `commands/harness.rs`, `setup.rs`, `main.rs`), `mecha-core` (`provider/router.rs`)

## Problem

`harness ruminate` and `harness null` call `corpus_slice` with no model, so it measures the model with the most runs, and the replays request that model. On a llama-server router a request naming a model loads it. The nightly job can therefore evict the owner's resident model to replay one they no longer use.

## Desired behaviour

The model to measure becomes a three-way pick:

- **Named** (typed by a person): no runs for it is an error.
- **Served** (the model a run here would use): no runs for it gives an empty slice under that model's name, never a different model.
- **Largest**: today's behaviour, kept only for `diagnose` when nothing resolves.

`corpus_slice` takes the pick.

**Resolving the served model.** Add a resolver to `setup.rs`. It uses the same order as `build`: `--model`, then the entry's model, then the provider default. It loads config the same way `prepare_tools` does.

**Router check.** If neither `--model` nor `--provider` was given and the entry is on a followed router, compare the resolved name with the router's resident model. Expose that model from `provider::router`'s snapshot. The check fails in two ways. A different resident model gives an error containing ``would load it over `<resident>` ``. An unknown resident model gives an error containing `cannot tell which model`.

**Using the pick.**

- `ruminate` and `null` use Named when global `--model` is given. Otherwise they use Served, and `--provider` alone does not change that.
- An empty slice prints a deferral naming the model, plus ` under <path>` when a workspace filter is set, and then succeeds.
- `diagnose` prefers Served and falls back to Largest.
- `harness null` takes the model hold, as `ruminate` does.
