# Experiment environments: the `requires` refusal says "never" about a feature an arm can switch on

**Crate:** `mecha-core` (`src/trial_env.rs`, `src/experiment.rs`)

## What is wrong

An experiment environment's `environment.toml` can list `requires`. When it names a feature no environment can switch on, `resolve_dir` refuses at load time. The message claims the feature "can never be on in a trial". That is wrong for features an arm's lever switches on. Today that means `messages`: an arm can list it in `levers_on`, and its config switch writes the feature's switch. The refusal is right, because `requires` is checked per environment before the levers apply. The wording sends the author away from the place that would actually work.

## Desired behaviour

- Add a function in `experiment` that, for a feature, finds the lever that switches it on, if there is one. Derive the answer, don't keep a list. For each lever in `Lever::ALL` that has a config switch, apply that switch (set on) to a default `Config`. A lever qualifies if the feature's switch owner (`Feature::switch_owner`) was not `Switch::On` before and is `Switch::On` after. Across all of `Feature::ALL`, only `messages` should map to a lever, the `messages` lever.
- Reword the refusal in `resolve_dir`. It must contain the text `` `<id>`, which no experiment environment can switch on `` and the text `only <the reachable list> can be on from one`. The reachable list is formatted as it is now.
- The advice clause depends on the feature:
  - If a lever switches the feature on, say to name it in the arm, including the literal text `levers_on = ["<lever name>"]`, and explain that this happens after `requires` is checked.
  - Otherwise keep the current fixture-server advice for `mail` and `docs`.
  - Otherwise keep the current wording that the feature stays out of every trial home. That wording must not appear for a lever-switched feature.
- Update the doc comment on `can_be_on_in_a_trial` so it says levers can switch on more. Its result does not change.

## Interface

In `mecha_core::experiment`:

```rust
pub fn lever_that_switches_on(f: crate::feature::Feature) -> Option<crate::harness::Lever>
```
