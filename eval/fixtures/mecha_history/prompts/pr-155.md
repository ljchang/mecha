# The served web page revalidates by date only, and a 304 carries no validators

**Crate:** `mecha-cli` (`Cargo.toml`, `src/commands/serve/mod.rs`)

## What is wrong

`mecha serve` serves the built web app through tower-http's `ServeDir`, and `cache_headers` marks the entry document `no-cache`, so a browser must revalidate it before each use. With the tower-http version in use (0.6), `ServeDir` dates what it serves but gives it no `ETag`. A browser can only revalidate by `If-Modified-Since`, and the `304` it gets back carries neither `ETag` nor `Last-Modified`, so it cannot refresh the validators on the entry it just confirmed. Date-only revalidation also depends on the clock's granularity: a rewrite inside the same second can be confirmed as unchanged.

tower-http 0.7's `ServeDir` adds strong `ETag`s (from size and mtime), answers `If-None-Match`, and puts both validators on a `304`.

## What fixed looks like

- `mecha-cli` depends on tower-http 0.7, with the `fs` feature as before. Update whatever the upgrade requires to keep building.
- The entry document is served with a strong `ETag` (not `W/`) and a `Last-Modified`.
- A request carrying a matching `If-None-Match` gets `304 Not Modified` with the same `ETag`, the same `Last-Modified`, and our `Cache-Control: no-cache` still on it.
- A `304` to `If-Modified-Since` also carries both validators.
- A stale tag (the document changed since, at a different length) gets `200` with the new document and a different `ETag`.
- The existing cache-header behaviour (`cache_headers`, the owner guard in front of the page) is unchanged.
