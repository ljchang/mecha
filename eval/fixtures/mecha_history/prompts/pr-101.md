# Distill can permanently record an incomplete Edit channel, and printed text can still carry line-rewriting controls

**Crates:** `mecha-core` (`src/outbox.rs`, `OutboxStore`), `mecha-cli` (`src/logs.rs`, `src/commands/distill.rs`)

## What is wrong

**The outbox read in `mecha distill`.** Episode tagging reads every outbox item so a session's goal errors can cite its drafts. `OutboxStore::items` skips any item file that fails to parse, with only a `tracing::warn!`, which is right for a listing. Distill then marks each session distilled, which is permanent: a session is never re-tagged. So one stray or unreadable-schema file in the outbox silently drops Edit-channel rows from every session distilled that night, with nothing visible (the nightly runs without `MECHA_LOG`). Saves to the store are temp-file-then-rename, so this is a persistent cause, not a half-written file that a retry would clear.

**Control characters in printed text.** `logs.rs` has a private `strip_ansi` that removes `ESC`-introduced sequences and lets every other control through. Its two callers in the log capture (`Writer::write` per line, and `release` for the unterminated tail on the way out) assume the stream was already split at `\n`, but `trim_end` only removes a trailing `\r`, so an interior one reaches the terminal or the TUI transcript. `release`'s tail is not stripped at all. Separately, `mecha distill` prints a session's surprise fields (`predicted`, `actual`, `about`) verbatim. They are a model's free-text reading of transcript content, may contain fetched or mailed text, and end up in a logfile read later. A bare `\r` there can overwrite the "untrusted" marker printed before it, and a `\n` can forge an extra line.

## What fixed looks like

**Outbox.**

- Add a strict read to `OutboxStore`: same order and same files as `items`, but a single item file that fails to parse fails the whole read, with an error that names that file's path.
- `items` keeps skipping and warning.
- `mecha distill` uses the strict read and fails the run with a clear error when it fails. A missing outbox store is still the ordinary empty case.

**Control characters.**

- Add a function in `logs.rs` that applies `strip_ansi` and then also removes every remaining Unicode control character (`char::is_control`) except tab. It also removes the line and paragraph separators U+2028 and U+2029, and the bidi embedding, override and isolate characters U+202A–U+202E and U+2066–U+2069. Everything else, non-Latin scripts included, passes through.
- `strip_ansi` keeps its current behaviour: it removes only `ESC` sequences, so a bare `\r` passes through it. Make it visible to the crate so it can be called from tests and the new function.
- Both log-capture sinks use the new function, including the tail `release` returns.
- `mecha distill` passes each surprise field (`predicted`, `actual`, and `about` when present) through it before printing, on the trusted and the untrusted branch alike.

## Interface

In `mecha_core::outbox`:

```rust
impl OutboxStore {
    pub fn items_strict(&self) -> Result<Vec<OutboxItem>>
}
```

In `mecha-cli`'s `src/logs.rs`:

```rust
pub(crate) fn strip_ansi(s: &str) -> String           // existing; behaviour unchanged
pub(crate) fn strip_ansi_and_controls(s: &str) -> String
```
