# Concurrent appends to one session file can merge two records into one line

**Crate:** `mecha-core` (`src/session.rs`, `Session::append`)

## What is wrong

Session transcripts are append-only JSONL: one JSON record per line. In normal use more than one writer touches the same session file at once. For example, the main run can be writing its records while a background task (such as the one that names the session) appends its own. Each writer opens the file in append mode and writes its record.

The record body and its trailing newline currently go out as **two separate writes**. `O_APPEND` makes each individual write land atomically at the end of the file, but it does nothing to keep a pair of writes together. If a second writer's record lands between the first writer's body and its newline, the file ends up with two JSON objects back to back on one line, followed by an empty line. That merged line does not parse. **Both records are lost** to anything that reads the transcript: replay, the run corpus, appraisal, resume.

This has not shown up in single-threaded tests, but it is a real race whenever several threads or processes append to one session.

## What fixed looks like

- However many threads append to the same `Session` concurrently, every line of the resulting file is exactly one complete, parseable JSON record. No line is torn and no line holds two merged records.
- The number of lines equals the header plus every record appended. Nothing is dropped and nothing is duplicated.
- Write failures still surface as errors with the session path in their context, as other I/O in this module does.
- The on-disk format does not change. Records stay one JSON object per line, newline-terminated, so existing transcripts and readers are unaffected.

Keep the change local to the append path. No locking scheme or new dependency should be needed.
