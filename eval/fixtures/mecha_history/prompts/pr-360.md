# `mecha rules` shows tallies over every model while retirement counts only one

**Crate:** `mecha-cli` (`src/commands/rules.rs`, the `list` view)

## What is wrong

The validation ledger (`ValidationRecord` rows, each carrying the `model` that drove it) can hold rows from more than one model, for instance a comparison arm beside the model in use. The `mecha rules` listing folds every row into the tallies it shows. `mecha rules propose-retirements`, by the owner's ruling, counts only the rows of the model in use. So when the ledger mixes models, a rule can look past its retirement threshold in the listing and never retire, and nothing on the screen says why the two disagree.

## What fixed looks like

- Add a helper that takes the ledger rows and returns a note when they hold more than one distinct `model`, and `None` when they hold one (or none). It is silent on a one-model ledger, where the two counts agree.
- The note says the tallies fold every model's rows, names the distinct models in sorted order joined by `", "`, says retirement counts only the model in use, and points at `mecha rules propose-retirements` for that count.
- The text listing prints the note, followed by a blank line, above the rest of the listing when there is one. The JSON output is unchanged.
- Read the ledger once in `list` and use it both for the tallies and for the note.

## Interface

In `mecha-cli`'s `src/commands/rules.rs`:

```rust
fn mixed_models_note(ledger: &[ValidationRecord]) -> Option<String>
```
